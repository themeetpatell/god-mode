# Test-Driven Development

## Workflow
1. Convert requirement into acceptance criteria.
2. Write failing tests or test plan first.
3. Implement the smallest code change to pass.
4. Add regression coverage for the bug class.
5. Verify with commands and expected outputs.

## Output
```
ACCEPTANCE CRITERIA:
TESTS TO ADD:
IMPLEMENTATION PLAN:
VERIFICATION COMMANDS:
REGRESSION RISKS:
```

## Rules
- Tests should reflect user behavior and failure modes.
- For UI work, include states: loading, empty, error, success.
